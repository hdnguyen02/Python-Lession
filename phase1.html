Lý thuyết — Python lưu biến thế nào trong bộ nhớ?

Trong Python, biến không chứa giá trị — biến chứa reference (địa chỉ tham chiếu) đến một object trên heap. Khi bạn viết a = [1, 2, 3], Python tạo object list trên heap và a trỏ đến nó.

Python identity.py 
# id() trả về địa chỉ bộ nhớ của object
a = [1, 2, 3]
b = a           # b và a cùng trỏ đến 1 object
c = [1, 2, 3]  # c là object MỚI, khác a

print(id(a) == id(b))  # True  — cùng object
print(id(a) == id(c))  # False — khác object

# is: so sánh identity (cùng object?)
# ==: so sánh equality (cùng giá trị?)
print(a is b)   # True  — cùng 1 object
print(a is c)   # False — khác object
print(a == c)   # True  — giá trị bằng nhau

# Khi b = a rồi b.append → a cũng thay đổi!
b.append(4)
print(a)  # [1, 2, 3, 4] ← a bị ảnh hưởng vì cùng object

Scope & Lifetime
LEGB rule · Local · Global · Enclosing · global keyword · Namespace
▼
Lý thuyết — Python tìm kiếm biến theo thứ tự nào?

Khi Python gặp một tên biến, nó tìm theo quy tắc LEGB: Local → Enclosing → Global → Built-in. Tìm thấy ở tầng nào thì dùng tầng đó, không tìm tiếp.

Python scope_legb.py 
x = "global"      # G — Global scope

def outer():
    x = "enclosing"  # E — Enclosing scope

    def inner():
        x = "local"  # L — Local scope
        print(x)    # "local" — tìm L trước

    inner()
    print(x)        # "enclosing"

outer()
print(x)          # "global"
print(len)         # B — Built-in (hàm có sẵn của Python)

# Đọc global bên trong hàm: OK
count = 0
def show_count():
    print(count)  # đọc được, không cần global

# Ghi global bên trong hàm: phải khai báo global
def increment():
    global count    # thông báo: count này là global
    count += 1

increment()
print(count)  # 1

Recursion — Đệ quy
Base case · Recursive case · Call stack · Factorial · Fibonacci
▼
Lý thuyết

Recursion là khi một hàm tự gọi chính nó. Mỗi hàm đệ quy phải có 2 phần: Base case (điều kiện dừng, không gọi đệ quy nữa) và Recursive case (gọi lại hàm với input nhỏ hơn). Thiếu base case → chạy mãi mãi → RecursionError.

Python recursion.py 
# Factorial: n! = n × (n-1) × ... × 1
def factorial(n):
    if n <= 1:          # BASE CASE — dừng đệ quy
        return 1
    return n * factorial(n - 1)  # RECURSIVE CASE

# Call stack khi gọi factorial(4):
# factorial(4) → 4 × factorial(3)
#   factorial(3) → 3 × factorial(2)
#     factorial(2) → 2 × factorial(1)
#       factorial(1) → 1  ← base case
#     ← 2 × 1 = 2
#   ← 3 × 2 = 6
# ← 4 × 6 = 24
print(factorial(5))  # 120

# Fibonacci: F(n) = F(n-1) + F(n-2)
def fib(n):
    if n <= 1:                    # base case
        return n
    return fib(n - 1) + fib(n - 2)  # recursive case

print([fib(i) for i in range(8)])
# [0, 1, 1, 2, 3, 5, 8, 13]
Python recursion_vs_loop.py 
# Khi nào dùng recursion thay vì loop?
# → Khi cấu trúc dữ liệu tự nhiên là đệ quy (cây, thư mục lồng nhau)

# Đếm files trong thư mục lồng nhau (recursion rất tự nhiên)
import os

def count_files(path):
    total = 0
    for item in os.listdir(path):
        full = os.path.join(path, item)
        if os.path.isfile(full):
            total += 1
        elif os.path.isdir(full):
            total += count_files(full)  # gọi lại với subdir
    return total

# Python giới hạn default recursion depth = 1000
# sys.setrecursionlimit(n) để thay đổi nếu cần
⚠️
Khi nào KHÔNG nên dùng recursion: Fibonacci đệ quy là ví dụ kinh điển về recursion kém hiệu quả — fib(40) gọi hàm hơn 300 triệu lần! Nếu cần performance, dùng loop + memo hoặc @functools.lru_cache.

# try/except — bắt nhiều loại lỗi
try:
    with open("config.json") as f:
        config = json.load(f)
except FileNotFoundError:
    print("File không tồn tại, dùng config mặc định")
    config = {"url": "http://localhost"}
except json.JSONDecodeError as e:
    print(f"JSON lỗi: {e}")
finally:
    print("Luôn chạy dòng này dù có lỗi hay không")

# Custom Exception — đặt tên lỗi rõ ràng
class TestDataError(Exception):

def load_test_user(data):

OOP là nền tảng của Page Object Model (POM) — pattern bắt buộc khi làm automation. Mỗi trang web sẽ là một class. Khi bạn hiểu OOP, việc học POM chỉ là áp dụng.

Python oop_basics.py 
# Khai báo class
class TestCase:
    # __init__ chạy khi tạo object mới
    def __init__(self, tc_id, name, module):
        self.tc_id   = tc_id    # instance attribute
        self.name    = name
        self.module  = module
        self.status  = "PENDING"  # giá trị mặc định
        self.duration = None

    def mark_pass(self, duration=0.0):
        self.status   = "PASS"
        self.duration = duration

    def mark_fail(self, reason=""):
        self.status = "FAIL"
        self.reason = reason

    def __repr__(self):
        return f"<TC {self.tc_id} | {self.status}>"


# Tạo object (instance)
tc1 = TestCase("TC001", "Login valid user", "auth")
tc1.mark_pass(1.5)
print(tc1)   # <TC TC001 | PASS>


# Kế thừa (Inheritance)
class TestSuite(TestCase):   # kế thừa từ TestCase
    def __init__(self, suite_id, name):
        super().__init__(suite_id, name, module="suite")
        self.test_cases = []

    def add_test(self, tc: TestCase):
        self.test_cases.append(tc)

    def report(self):
        total  = len(self.test_cases)
        passed = sum(1 for t in self.test_cases if t.status == "PASS")
        print(f"Suite: {self.name} — {passed}/{total} passed")
self là gì — giải thích thật đơn giản

Đây là câu hỏi mà hầu hết người mới đều thắc mắc. Python không tự biết method đang chạy cho object nào — nên bạn phải truyền object đó vào thủ công. Tên self chỉ là quy ước, bạn đặt tên khác cũng được (nhưng đừng làm vậy).

Python self_explained.py 
# Khi bạn gọi:
tc1.mark_pass(1.5)

# Python ngầm dịch thành:
TestCase.mark_pass(tc1, 1.5)
# → self chính là tc1 bên trong method!

# Nếu không có self, method không biết
# đang chỉnh status của tc1 hay tc2:
tc1 = TestCase("TC001", "Login", "auth")
tc2 = TestCase("TC002", "Logout", "auth")

tc1.mark_pass()   # self = tc1  → chỉ tc1.status đổi
tc2.mark_fail()   # self = tc2  → chỉ tc2.status đổi

print(tc1.status)  # PASS
print(tc2.status)  # FAIL
💡
Quy tắc nhớ: Mỗi method muốn truy cập data của chính object đó thì phải có self làm tham số đầu tiên. Không có self → method không biết mình đang làm việc với object nào.
Class attribute vs Instance attribute

Hai loại attribute này hoạt động rất khác nhau — nhầm lẫn chỗ này sẽ gây bug khó tìm. Class attribute được chia sẻ chung cho tất cả object. Instance attribute thuộc riêng từng object, khai báo bên trong __init__ qua self.

Python class_vs_instance_attr.py 
class TestCase:
    # Class attribute — dùng chung, khai báo ngoài __init__
    category = "functional"
    count    = 0   # đếm tổng số TC đã tạo

    def __init__(self, tc_id, name):
        # Instance attribute — riêng của từng object
        self.tc_id  = tc_id
        self.name   = name
        self.status = "PENDING"
        TestCase.count += 1   # tăng bộ đếm chung


tc1 = TestCase("TC001", "Login")
tc2 = TestCase("TC002", "Logout")

# Class attribute — truy cập qua tên class hoặc object
print(TestCase.category)   # functional
print(tc1.category)        # functional (kế thừa từ class)
print(TestCase.count)      # 2  (tc1 + tc2)

# Instance attribute — riêng từng object
print(tc1.tc_id)            # TC001
print(tc2.tc_id)            # TC002

# ⚠️ Cẩn thận: gán qua object tạo instance attr mới,
#    không đổi class attr!
tc1.category = "regression"   # tạo instance attr riêng cho tc1
print(tc1.category)            # regression (instance attr)
print(tc2.category)            # functional  (class attr gốc)
print(TestCase.category)      # functional  (không đổi)
⚠️
Dễ nhầm: Nếu class attribute là mutable (list, dict), tất cả object dùng chung cùng một object đó. Thay đổi từ một object → ảnh hưởng hết. Luôn khai báo list/dict mặc định bên trong __init__ qua self để tránh lỗi này.
Kế thừa — is-a hay has-a?

Kế thừa chỉ hợp lý khi có quan hệ "is-a" (là một loại của). Dùng sai sẽ khiến code khó hiểu và khó sửa. Kiểm tra nhanh: đọc câu "A là một B" — nếu câu đó nghe tự nhiên thì kế thừa đúng, nếu nghe gượng thì dùng composition (has-a) thay vào.

Python inheritance_vs_composition.py 
# ✅ is-a → dùng kế thừa hợp lý
# "AutomatedTestCase là một loại TestCase" → đúng
class AutomatedTestCase(TestCase):
    def __init__(self, tc_id, name, script_path):
        super().__init__(tc_id, name)
        self.script_path = script_path

    def run(self):
        print(f"Chạy script: {self.script_path}")
        self.mark_pass()   # dùng method kế thừa từ TestCase


# ❌ has-a → KHÔNG nên kế thừa
# "TestSuite là một loại TestCase" → nghe sai!
# TestSuite CHỨA nhiều TestCase → dùng composition
class TestSuite:   # không kế thừa TestCase
    def __init__(self, name):
        self.name       = name
        self.test_cases = []   # has-a: chứa list TestCase

    def add(self, tc: TestCase):
        self.test_cases.append(tc)

    def report(self):
        total  = len(self.test_cases)
        passed = sum(1 for t in self.test_cases if t.status == "PASS")
        print(f"[{self.name}] {passed}/{total} passed")


# Kết hợp: tạo suite, thêm các TC vào
suite = TestSuite("Smoke Test")
tc_auto = AutomatedTestCase("TC001", "Login", "tests/login.py")
tc_auto.run()
suite.add(tc_auto)
suite.report()   # [Smoke Test] 1/1 passed
💡
Liên hệ POM: Trong Page Object Model sau này, mỗi page sẽ kế thừa từ một BasePage (vì "LoginPage là một loại BasePage"). BasePage chứa các method dùng chung như find_element(), click(). Đây chính là is-a thực tế trong automation.

Lý thuyết — Thuật toán cơ bản

Thuật toán là chuỗi bước có thứ tự để giải quyết vấn đề. Trước khi code, hãy chia vấn đề thành các bước nhỏ (Problem Decomposition). Bốn thuật toán dưới đây là nền tảng — hiểu chúng giúp bạn đọc và đánh giá code tốt hơn.

Python search.py 
# LINEAR SEARCH — duyệt từng phần tử O(n)
def linear_search(lst, target):
    for i, val in enumerate(lst):
        if val == target:
            return i       # trả về index
    return -1           # không tìm thấy

nums = [3, 7, 1, 9, 4]
print(linear_search(nums, 9))  # 3

# BINARY SEARCH — list PHẢI sắp xếp trước, O(log n)
def binary_search(lst, target):
    left, right = 0, len(lst) - 1
    while left <= right:
        mid = (left + right) // 2
        if lst[mid] == target:   return mid
        elif lst[mid] < target:  left  = mid + 1
        else:                    right = mid - 1
    return -1

sorted_nums = [1, 3, 5, 7, 9, 11]
print(binary_search(sorted_nums, 7))  # 3
Python sorting.py 
# BUBBLE SORT — đổi chỗ cặp liền kề, O(n²)
def bubble_sort(lst):
    n = len(lst)
    for i in range(n):
        for j in range(0, n - i - 1):
            if lst[j] > lst[j + 1]:
                lst[j], lst[j + 1] = lst[j + 1], lst[j]
    return lst

print(bubble_sort([64, 34, 25, 12, 22]))
# [12, 22, 25, 34, 64]

# INSERTION SORT — chèn phần tử vào đúng vị trí, O(n²)
# Tốt hơn Bubble Sort khi mảng gần như đã sắp xếp
def insertion_sort(lst):
    for i in range(1, len(lst)):
        key = lst[i]
        j = i - 1
        while j >= 0 and lst[j] > key:
            lst[j + 1] = lst[j]
            j -= 1
        lst[j + 1] = key
    return lst

print(insertion_sort([5, 2, 4, 6, 1]))
# [1, 2, 4, 5, 6]
💡
Tại sao học nếu đã có sorted()? Python built-in tốt hơn, nhưng hiểu thuật toán giúp bạn: (1) đọc code người khác, (2) giải bài toán tùy biến, (3) phỏng vấn kỹ thuật. Binary Search đặc biệt quan trọng — xuất hiện thường xuyên trong thực tế.

# O(1) — không phụ thuộc n
def get_first(lst):    return lst[0]   # luôn 1 bước
def lookup(d, k):      return d[k]     # hash table → O(1)

# O(n) — tỷ lệ thuận với n
def find_max(lst):
    max_val = lst[0]
    for x in lst:          # duyệt 1 lần
        if x > max_val: max_val = x
    return max_val

# O(n²) — 2 vòng lặp lồng nhau
def has_dup_slow(lst):
    for i in range(len(lst)):
        for j in range(i + 1, len(lst)):
            if lst[i] == lst[j]: return True
    return False

# O(n) với set — trade-off: tốn thêm O(n) space
def has_dup_fast(lst):
    return len(lst) != len(set(lst))

# Đo thời gian thực tế
import time
n = [i for i in range(10_000)]
t0 = time.time(); has_dup_slow(n); print(f"O(n²): {time.time()-t0:.3f}s")
t0 = time.time(); has_dup_fast(n); print(f"O(n):  {time.time()-t0:.3f}s")
💡
Quy tắc thực hành: Khi thấy code chậm, nhìn vào vòng lặp lồng nhau trước — thường là O(n²). Trong Python, set/dict lookup là O(1) nhờ hash table — ưu tiên hơn duyệt list khi cần kiểm tra tồn tại. Space complexity cũng quan trọng: đôi khi nên đánh đổi tốn memory để được thời gian nhanh hơn.
