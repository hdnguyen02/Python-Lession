Lý thuyết — Python lưu biến thế nào trong bộ nhớ?

Trong Python, biến không chứa giá trị — biến chứa reference (địa chỉ tham chiếu) đến một object trên heap. Khi bạn viết a = [1, 2, 3], Python tạo object list trên heap và a trỏ đến nó.

Python identity.py 
# id() trả về địa chỉ bộ nhớ của object
a = [1, 2, 3]
b = a           # b và a cùng trỏ đến 1 object
c = [1, 2, 3]  # c là object MỚI, khác a

print(id(a) == id(b))  # True  — cùng object
print(id(a) == id(c))  # False — khác object

# is: so sánh identity (cùng object?)
# ==: so sánh equality (cùng giá trị?)
print(a is b)   # True  — cùng 1 object
print(a is c)   # False — khác object
print(a == c)   # True  — giá trị bằng nhau

# Khi b = a rồi b.append → a cũng thay đổi!
b.append(4)
print(a)  # [1, 2, 3, 4] ← a bị ảnh hưởng vì cùng object

Scope & Lifetime
LEGB rule · Local · Global · Enclosing · global keyword · Namespace
▼
Lý thuyết — Python tìm kiếm biến theo thứ tự nào?

Khi Python gặp một tên biến, nó tìm theo quy tắc LEGB: Local → Enclosing → Global → Built-in. Tìm thấy ở tầng nào thì dùng tầng đó, không tìm tiếp.

Python scope_legb.py 
x = "global"      # G — Global scope

def outer():
    x = "enclosing"  # E — Enclosing scope

    def inner():
        x = "local"  # L — Local scope
        print(x)    # "local" — tìm L trước

    inner()
    print(x)        # "enclosing"

outer()
print(x)          # "global"
print(len)         # B — Built-in (hàm có sẵn của Python)

# Đọc global bên trong hàm: OK
count = 0
def show_count():
    print(count)  # đọc được, không cần global

# Ghi global bên trong hàm: phải khai báo global
def increment():
    global count    # thông báo: count này là global
    count += 1

increment()
print(count)  # 1

Recursion — Đệ quy
Base case · Recursive case · Call stack · Factorial · Fibonacci
▼
Lý thuyết

Recursion là khi một hàm tự gọi chính nó. Mỗi hàm đệ quy phải có 2 phần: Base case (điều kiện dừng, không gọi đệ quy nữa) và Recursive case (gọi lại hàm với input nhỏ hơn). Thiếu base case → chạy mãi mãi → RecursionError.

Python recursion.py 
# Factorial: n! = n × (n-1) × ... × 1
def factorial(n):
    if n <= 1:          # BASE CASE — dừng đệ quy
        return 1
    return n * factorial(n - 1)  # RECURSIVE CASE

# Call stack khi gọi factorial(4):
# factorial(4) → 4 × factorial(3)
#   factorial(3) → 3 × factorial(2)
#     factorial(2) → 2 × factorial(1)
#       factorial(1) → 1  ← base case
#     ← 2 × 1 = 2
#   ← 3 × 2 = 6
# ← 4 × 6 = 24
print(factorial(5))  # 120

# Fibonacci: F(n) = F(n-1) + F(n-2)
def fib(n):
    if n <= 1:                    # base case
        return n
    return fib(n - 1) + fib(n - 2)  # recursive case

print([fib(i) for i in range(8)])
# [0, 1, 1, 2, 3, 5, 8, 13]
Python recursion_vs_loop.py 
# Khi nào dùng recursion thay vì loop?
# → Khi cấu trúc dữ liệu tự nhiên là đệ quy (cây, thư mục lồng nhau)

# Đếm files trong thư mục lồng nhau (recursion rất tự nhiên)
import os

def count_files(path):
    total = 0
    for item in os.listdir(path):
        full = os.path.join(path, item)
        if os.path.isfile(full):
            total += 1
        elif os.path.isdir(full):
            total += count_files(full)  # gọi lại với subdir
    return total

# Python giới hạn default recursion depth = 1000
# sys.setrecursionlimit(n) để thay đổi nếu cần
⚠️
Khi nào KHÔNG nên dùng recursion: Fibonacci đệ quy là ví dụ kinh điển về recursion kém hiệu quả — fib(40) gọi hàm hơn 300 triệu lần! Nếu cần performance, dùng loop + memo hoặc @functools.lru_cache.

Class & Object — Nền tảng

Class là bản thiết kế. Object (instance) là thực thể cụ thể tạo từ bản thiết kế đó. Một class có thể tạo nhiều object, mỗi object có data riêng của nó.

Python animal.py 
class Animal:
    # Class attribute — dùng chung cho tất cả object
    kingdom = "Animalia"
    count   = 0

    def __init__(self, name: str, species: str, age: int):
        # Instance attribute — riêng của từng object
        self.name    = name
        self.species = species
        self.age     = age
        Animal.count += 1   # tăng bộ đếm chung

    def describe(self) -> str:
        return f"{self.name} là {self.species}, {self.age} tuổi"

    def birthday(self):
        self.age += 1
        print(f"{self.name} vừa sinh nhật! Giờ {self.age} tuổi.")

    def __str__(self):       # print(obj) gọi cái này
        return self.describe()

    def __repr__(self):      # repr(obj) — debug friendly
        return f"Animal(name={self.name!r}, species={self.species!r})"


# Tạo object (instance)
dog  = Animal("Rex",   "Chó Golden", 3)
cat  = Animal("Luna",  "Mèo Anh",   2)

print(dog)              # Rex là Chó Golden, 3 tuổi
print(Animal.count)     # 2
print(dog.kingdom)      # Animalia (class attribute)
dog.birthday()          # Rex vừa sinh nhật! Giờ 4 tuổi.
print(cat.age)          # 2 — cat không bị ảnh hưởng
💡
self là gì? Python không tự biết method đang chạy cho object nào — nên bạn phải truyền object đó vào. dog.birthday() Python ngầm dịch thành Animal.birthday(dog). self chính là dog bên trong method. Tên "self" chỉ là quy ước, có thể đặt tên khác nhưng đừng làm vậy.
⚠️
Class attribute mutable — cẩn thận! Nếu class attribute là list/dict, tất cả object dùng chung cùng một object. Luôn khai báo list/dict bên trong __init__ qua self để tránh bug chia sẻ ngoài ý muốn.
1. Encapsulation — Đóng gói

Đóng gói là việc che giấu data nội tại và chỉ cho phép truy cập qua các method được kiểm soát. Điều này ngăn code bên ngoài vô tình làm hỏng dữ liệu bên trong object.

Python bank_account.py 
class BankAccount:
    def __init__(self, owner: str, balance: float = 0):
        self.owner    = owner          # public — ai cũng đọc/ghi được
        self._balance = balance        # _protected — quy ước: không đụng từ ngoài
        self.__log    = []             # __private — name mangling, khó truy cập hơn

    # @property — gọi như attribute, thực ra là method getter
    @property
    def balance(self) -> float:
        return self._balance

    def deposit(self, amount: float):
        if amount <= 0:
            raise ValueError("Số tiền phải dương")
        self._balance += amount
        self.__log.append(f"+{amount:,.0f}")

    def withdraw(self, amount: float):
        if amount > self._balance:
            raise ValueError("Số dư không đủ")
        self._balance -= amount
        self.__log.append(f"-{amount:,.0f}")

    def history(self) -> list:
        return self.__log.copy()    # trả về bản copy, không lộ list gốc


acc = BankAccount("Alice", 1_000_000)
acc.deposit(500_000)
acc.withdraw(200_000)
print(acc.balance)     # 1300000 — dùng @property như attribute bình thường
print(acc.history())  # ['+500,000', '-200,000']

# acc.__log       → AttributeError  (name mangling bảo vệ)
# acc._balance = -999  → được về mặt kỹ thuật nhưng vi phạm quy ước
Ký hiệu Loại Truy cập từ ngoài class
name Public ✅ Thoải mái
_name Protected (quy ước) ⚠️ Được, nhưng không nên
__name Private (name mangling) ❌ Dùng method/property thay thế
2. Inheritance — Kế thừa

Class con tự động có tất cả attribute và method của class cha. Dùng super() để gọi method cha. Class con có thể override (ghi đè) method cha để thay đổi hành vi.

Python inheritance.py 
class Animal:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age  = age

    def speak(self) -> str:
        return "..."

    def describe(self):
        print(f"{self.name} ({self.age} tuổi): {self.speak()}")


class Dog(Animal):          # Dog kế thừa Animal
    def __init__(self, name, age, breed: str):
        super().__init__(name, age)  # gọi __init__ của Animal
        self.breed = breed            # thêm attribute mới

    def speak(self) -> str:     # override — ghi đè method cha
        return "Gâu gâu!"

    def fetch(self):           # method riêng của Dog
        print(f"{self.name} đi nhặt bóng!")


class Cat(Animal):
    def speak(self) -> str:
        return "Meo~"


rex  = Dog("Rex", 3, "Golden")
luna = Cat("Luna", 2)
rex.describe()    # Rex (3 tuổi): Gâu gâu!
luna.describe()   # Luna (2 tuổi): Meo~
rex.fetch()       # Rex đi nhặt bóng!

# Dog kế thừa từ Animal → isinstance trả True cho cả 2
print(isinstance(rex, Dog))     # True
print(isinstance(rex, Animal))  # True
print(issubclass(Dog, Animal))  # True
💡
is-a hay has-a? Kế thừa chỉ hợp lý khi có quan hệ "là một loại của". "Dog là một loại Animal" → đúng, kế thừa OK. "AnimalShelter là một loại Animal" → nghe sai → không kế thừa, thay bằng composition: self.animals = [].
3. Polymorphism — Đa hình

Đa hình cho phép xử lý nhiều loại object khác nhau theo cùng một interface. Code gọi animal.speak() mà không cần biết đó là Dog hay Cat — mỗi object tự biết cách phản hồi.

Python polymorphism.py 
class Bird(Animal):
    def speak(self) -> str:
        return "Chip chip!"


# POLYMORPHISM — cùng method describe(), hành vi khác nhau
zoo = [
    Dog("Rex",    3, "Golden"),
    Cat("Luna",   2),
    Bird("Tweety", 1),
]

for animal in zoo:
    animal.describe()          # gọi cùng method, output khác nhau
# Rex (3 tuổi): Gâu gâu!
# Luna (2 tuổi): Meo~
# Tweety (1 tuổi): Chip chip!

# DUCK TYPING — Python không check type, chỉ cần object có method đúng tên
class Robot:                       # không kế thừa Animal
    name, age = "R2D2", 5
    def speak(self): return "Beep boop!"
    def describe(self):
        print(f"{self.name}: {self.speak()}")

# Robot cũng chạy được trong loop — "nếu nó có describe(), thì dùng được"
for obj in zoo + [Robot()]:
    obj.describe()    # duck typing: không cần kế thừa Animal
4. Abstraction — Trừu tượng hóa

Abstraction định nghĩa interface bắt buộc mà tất cả class con phải implement. Python dùng module abc. Class abstract không thể tạo object trực tiếp — phải subclass rồi implement hết method abstract mới dùng được.

Python abstraction.py 
from abc import ABC, abstractmethod

class Shape(ABC):          # Abstract class — không tạo instance được
    def __init__(self, color: str):
        self.color = color

    @abstractmethod
    def area(self) -> float:        # BẮT BUỘC class con phải implement
        pass

    @abstractmethod
    def perimeter(self) -> float:
        pass

    def describe(self):             # method thường — class con kế thừa luôn
        print(f"{type(self).__name__} màu {self.color}: "
              f"diện tích={self.area():.2f}, chu vi={self.perimeter():.2f}")


class Circle(Shape):
    def __init__(self, color, radius: float):
        super().__init__(color)
        self.radius = radius

    def area(self) -> float:
        return 3.14159 * self.radius ** 2

    def perimeter(self) -> float:
        return 2 * 3.14159 * self.radius


class Rectangle(Shape):
    def __init__(self, color, w: float, h: float):
        super().__init__(color)
        self.w, self.h = w, h

    def area(self) -> float:      return self.w * self.h
    def perimeter(self) -> float: return 2 * (self.w + self.h)


# Shape()  → TypeError: Can't instantiate abstract class
shapes = [Circle("đỏ", 5), Rectangle("xanh", 4, 6)]
for s in shapes:
    s.describe()
# Circle màu đỏ: diện tích=78.54, chu vi=31.42
# Rectangle màu xanh: diện tích=24.00, chu vi=20.00

# Polymorphism + Abstraction kết hợp
def total_area(shapes: list) -> float:
    return sum(s.area() for s in shapes)  # không cần biết loại shape

print(total_area(shapes))   # 102.54
💡
Khi nào dùng Abstraction? Khi muốn bắt buộc tất cả class con implement một số method nhất định — ví dụ mọi nguồn dữ liệu phải có read() và write(), mọi loại thanh toán phải có process(). Lỗi thiếu implement được phát hiện sớm ngay lúc __init__, không phải khi gọi method.

Lý thuyết — Thuật toán cơ bản

Thuật toán là chuỗi bước có thứ tự để giải quyết vấn đề. Trước khi code, hãy chia vấn đề thành các bước nhỏ (Problem Decomposition). Bốn thuật toán dưới đây là nền tảng — hiểu chúng giúp bạn đọc và đánh giá code tốt hơn.

Python search.py 
# LINEAR SEARCH — duyệt từng phần tử O(n)
def linear_search(lst, target):
    for i, val in enumerate(lst):
        if val == target:
            return i       # trả về index
    return -1           # không tìm thấy

nums = [3, 7, 1, 9, 4]
print(linear_search(nums, 9))  # 3

# BINARY SEARCH — list PHẢI sắp xếp trước, O(log n)
def binary_search(lst, target):
    left, right = 0, len(lst) - 1
    while left <= right:
        mid = (left + right) // 2
        if lst[mid] == target:   return mid
        elif lst[mid] < target:  left  = mid + 1
        else:                    right = mid - 1
    return -1

sorted_nums = [1, 3, 5, 7, 9, 11]
print(binary_search(sorted_nums, 7))  # 3
Python sorting.py 
# BUBBLE SORT — đổi chỗ cặp liền kề, O(n²)
def bubble_sort(lst):
    n = len(lst)
    for i in range(n):
        for j in range(0, n - i - 1):
            if lst[j] > lst[j + 1]:
                lst[j], lst[j + 1] = lst[j + 1], lst[j]
    return lst

print(bubble_sort([64, 34, 25, 12, 22]))
# [12, 22, 25, 34, 64]

# INSERTION SORT — chèn phần tử vào đúng vị trí, O(n²)
# Tốt hơn Bubble Sort khi mảng gần như đã sắp xếp
def insertion_sort(lst):
    for i in range(1, len(lst)):
        key = lst[i]
        j = i - 1
        while j >= 0 and lst[j] > key:
            lst[j + 1] = lst[j]
            j -= 1
        lst[j + 1] = key
    return lst

print(insertion_sort([5, 2, 4, 6, 1]))
# [1, 2, 4, 5, 6]
💡
Tại sao học nếu đã có sorted()? Python built-in tốt hơn, nhưng hiểu thuật toán giúp bạn: (1) đọc code người khác, (2) giải bài toán tùy biến, (3) phỏng vấn kỹ thuật. Binary Search đặc biệt quan trọng — xuất hiện thường xuyên trong thực tế.
